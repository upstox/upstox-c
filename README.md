# Upstox C SDK for API v2

## Introduction

The official C client for communicating with the <a href="https://upstox.com/trading-api/">Upstox API</a>.

Upstox API is a set of rest APIs that provide data required to build a complete investment and trading platform. Execute orders in real time, manage user portfolio, stream live market data (using Websocket), and more, with the easy to understand API collection.

- API version: v2
- Package version: 1.0.0 (`UPSTOX_SDK_VERSION` in `upstox_client/upstox.h`)
- Build package: org.openapitools.codegen.languages.CLibcurlClientCodegen

The REST client is generated by [OpenAPI Generator](https://openapi-generator.tech) 7.23.0 (`-g c`, libcurl + cJSON) from the same Upstox spec as the other Upstox SDKs, plus hand-written routing, sandbox and WebSocket code.

## Requirements

- A C99 compiler and CMake 3.x
- libcurl 7.58 or later; the WebSocket feeder needs **libcurl 7.86 or later built with WebSocket support** (e.g. Homebrew `curl`; the macOS system libcurl may lack it)
- [protobuf-c](https://github.com/protobuf-c/protobuf-c) for the WebSocket feeder (without it, only the REST library is built)

On macOS:

```sh
brew install cmake curl protobuf-c
```

On Debian/Ubuntu: `apt install cmake libcurl4-openssl-dev libprotobuf-c-dev`.

## Build & Install

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=$(brew --prefix curl)   # drop the prefix path on Linux
cmake --build build -j8
cmake --install build --prefix /usr/local                       # optional
```

This builds the `upstox_client` library (REST API) and, when protobuf-c is found, the `upstox_feeder` library (WebSocket streamers). Options:

| Option | Default | Effect |
|---|---|---|
| `BUILD_SHARED_LIBS` | `ON` | shared (`ON`) or static libraries |
| `UPSTOX_BUILD_EXAMPLES` | `OFF` | also builds the [strategy](examples/strategies/) and [websocket](examples/websocket/) programs |

To use the SDK from your own CMake project, add it as a subdirectory and link `upstox_client`, plus `upstox_feeder` for streaming. Headers are included from the repository root. After `cmake --install`, compile with `-I<prefix>/include` and link `-lupstox_client` (and `-lupstox_feeder -lprotobuf-c`):

```cmake
add_subdirectory(upstox-c)
target_link_libraries(my_app PRIVATE upstox_client)
```

## Getting Started

```c
#include <stdio.h>
#include "upstox_client/upstox.h"
#include "upstox_client/api/UserAPI.h"

int main(void) {
    apiClient_setupGlobalEnv();
    apiClient_t *client = upstox_client_create("{your_access_token}");

    get_profile_response_t *resp = UserAPI_getProfile(client);
    if (resp == NULL) {
        printf("Error: HTTP %ld %s\n", client->response_code, client->errorBody ? client->errorBody : "");
    } else {
        if (resp->data != NULL) {
            printf("%s\n", resp->data->user_name);
        }
        get_profile_response_free(resp);
    }

    apiClient_free(client);
    apiClient_unsetupGlobalEnv();
    return 0;
}
```

Every call has the same shape: `<Tag>API_<operationId>(client, <params>)`, e.g. `OrderV3API_placeOrderV3(client, body, algo_name)` or `HistoryV3API_getIntraDayCandleDataV3(client, key, unit, &interval)`. Pass `NULL` for an optional parameter; optional numbers are pointers (`int *`), so pass the address of a local. Each call returns a heap-allocated response model that you free with its `<model>_free`, or `NULL` on failure.

Call `apiClient_setupGlobalEnv()` once before any client is created (before starting threads) and `apiClient_unsetupGlobalEnv()` once at exit. An `apiClient_t` is not thread-safe; use one per thread.

## Package Layout

| Path | Contents |
|---|---|
| `upstox_client/upstox.h`, `upstox_client/upstox.c` | `upstox_client_create`, `upstox_sandbox_client_create`, HFT and sandbox routing, SDK headers (hand-written) |
| `upstox_client/api/` | one header per API tag (`OrderAPI.h`, `OrderV3API.h`, `UserAPI.h`, `MarketQuoteV3API.h`, ...) |
| `upstox_client/models/` | request and response models (`<model>_create`, `_parseFromJSON`, `_convertToJSON`, `_free`) |
| `upstox_client/include/` | `apiClient.h` (`apiClient_t`), `list.h` (`list_t`), `keyValuePair.h`, `binary.h` |
| `upstox_client/src/` | `apiClient.c` (libcurl transport), `list.c`, `apiKey.c`, `binary.c` |
| `upstox_client/external/` | bundled [cJSON](https://github.com/DaveGamble/cJSON) |
| `upstox_client/feeder/` | WebSocket streamers (`market_data_streamer_v3.h`, `portfolio_data_streamer.h`) and the protobuf-c feed types; CMake target `upstox_feeder` |

Include headers relative to the repository root, or to `<prefix>/include` after `cmake --install` (the installed tree has the same `upstox_client/...` layout, feeder headers included):

```c
#include "upstox_client/upstox.h"
#include "upstox_client/api/OrderV3API.h"
```

## Configuration

`upstox_client_create(token)` returns a client for `https://api.upstox.com` that sends the token as a Bearer token. Order place, modify and cancel calls (v2, v3, multi-order and GTT) are sent to `https://api-hft.upstox.com`; everything else, including US stock orders (`/v2/us/...`), goes to `api.upstox.com`.

To send calls to another host (a proxy or a test server), create the client with a custom base path; HFT routing is then disabled and every call goes to that host:

```c
#include <string.h>
#include "upstox_client/upstox.h"

int main(void) {
    apiClient_setupGlobalEnv();
    apiClient_t *client = apiClient_create_with_base_path("http://localhost:8080", NULL);
    client->accessToken = strdup("{your_access_token}");

    // ... calls ...

    apiClient_free(client);
    apiClient_unsetupGlobalEnv();
    return 0;
}
```

### Sandbox Mode

We recommend using the sandbox environment for testing purposes. To enable sandbox mode, create the client with `upstox_sandbox_client_create`.

```c
#include <stdio.h>
#include <string.h>
#include "upstox_client/upstox.h"
#include "upstox_client/api/OrderV3API.h"

int main(void) {
    apiClient_setupGlobalEnv();
    apiClient_t *client = upstox_sandbox_client_create("{your_sandbox_access_token}");

    int quantity = 1;
    double price = 9.12;
    int slice = 1;
    int disclosed_quantity = 0;
    double trigger_price = 0;
    int is_amo = 1;
    place_order_v3_request_t *order = place_order_v3_request_create(
        &quantity, upstox_client_place_order_v3_request_PRODUCT_D, upstox_client_place_order_v3_request_VALIDITY_DAY, &price, strdup("string"),
        &slice, strdup("NSE_EQ|INE669E01016"), upstox_client_place_order_v3_request_ORDERTYPE_LIMIT,
        upstox_client_place_order_v3_request_TRANSACTIONTYPE_BUY, &disclosed_quantity, &trigger_price, &is_amo, NULL);

    place_order_v3_response_t *resp = OrderV3API_placeOrderV3(client, order, NULL);
    if (resp == NULL) {
        printf("Error: HTTP %ld %s\n", client->response_code, client->errorBody ? client->errorBody : "");
    } else {
        if (resp->data != NULL) {
            listEntry_t *entry;
            list_ForEach(entry, resp->data->order_ids) {
                printf("%s\n", (char *)entry->data);
            }
        }
        place_order_v3_response_free(resp);
    }
    place_order_v3_request_free(order);

    apiClient_free(client);
    apiClient_unsetupGlobalEnv();
    return 0;
}
```

The sandbox serves only order place, modify and cancel (v2 and v3) and multi-order place. Any other call on a sandbox client returns `NULL` with `response_code` 0 without being sent.
To learn more about the sandbox environment and the available sandbox APIs, please visit the [Upstox API documentation - Sandbox](https://upstox.com/developer/api-documentation/sandbox).

## Error Handling

A call returns `NULL` when it fails. Then:

- `client->response_code` is the HTTP status, or 0 when nothing was received (network error, or a call the sandbox does not serve);
- `client->errorBody` is the raw error JSON from Upstox (error code and message), or `NULL`. It stays valid until the next call on that client.

```c
cancel_order_v3_response_t *resp = OrderV3API_cancelOrderV3(client, "2501211050101", NULL);
if (resp == NULL) {
    fprintf(stderr, "HTTP %ld: %s\n", client->response_code, client->errorBody ? client->errorBody : "");
}
```

Parse `errorBody` with `cJSON_Parse` to read `errors[0].errorCode` and `errors[0].message`.

## Memory Ownership

- **Responses:** every returned model is yours; free it with `<model>_free`, which frees nested models, lists and strings too.
- **`<model>_create(...)`:** copies numeric pointer arguments (`int *`, `double *`), so the address of a local is fine. It **takes ownership** of string, model and `list_t` arguments, which `<model>_free` frees — pass `strdup("...")`, never a string literal or a buffer you free yourself.
- **Request bodies:** API calls do not free the request you pass; free it with `<model>_free` after the call.
- **Top-level list bodies** (`OrderAPI_placeMultiOrder`, `UserAPI_updateKillSwitch`): build a `list_t` with `list_createList()` / `list_addElement()`, then free each element with its `<model>_free` and the list with `list_freeList()`.
- **`<model>_parseFromJSON(cJSON *)`** returns a new model (free with `_free`) and does not take the cJSON; **`<model>_convertToJSON(model)`** returns a new `cJSON *` (free with `cJSON_Delete`). Free strings from `cJSON_Print` with `cJSON_free`.
- String parameters of API calls (`char *order_id`, ...) are copied; string literals are fine there.

Enum fields use `upstox_client_<model>_<FIELD>_e` values (e.g. `upstox_client_place_order_v3_request_PRODUCT_D`), and each enum has `<model>_<field>_ToString` / `_FromString`. Map responses (market quotes) are `list_t`s of `keyValuePair_t` whose `value` is the model.

## Algo Name Support

The SDK supports passing an algorithm name for order tracking and management. Order functions take it as their last parameter (`X_Algo_Name`) and send it as the `X-Algo-Name` header; pass `NULL` to omit it.

```c
#include <stdio.h>
#include <string.h>
#include "upstox_client/upstox.h"
#include "upstox_client/api/OrderV3API.h"

int main(void) {
    apiClient_setupGlobalEnv();
    apiClient_t *client = upstox_client_create("{your_access_token}");

    int quantity = 1;
    double price = 20;
    int slice = 1;
    int disclosed_quantity = 0;
    double trigger_price = 0;
    int is_amo = 0;
    place_order_v3_request_t *order = place_order_v3_request_create(
        &quantity, upstox_client_place_order_v3_request_PRODUCT_D, upstox_client_place_order_v3_request_VALIDITY_DAY, &price, NULL, &slice,
        strdup("NSE_EQ|INE528G01035"), upstox_client_place_order_v3_request_ORDERTYPE_LIMIT,
        upstox_client_place_order_v3_request_TRANSACTIONTYPE_BUY, &disclosed_quantity, &trigger_price, &is_amo, NULL);

    place_order_v3_response_t *resp = OrderV3API_placeOrderV3(client, order, "your-algo-name");
    if (resp == NULL) {
        printf("Error: HTTP %ld %s\n", client->response_code, client->errorBody ? client->errorBody : "");
    } else {
        if (resp->data != NULL) {
            listEntry_t *entry;
            list_ForEach(entry, resp->data->order_ids) {
                printf("%s\n", (char *)entry->data);
            }
        }
        place_order_v3_response_free(resp);
    }
    place_order_v3_request_free(order);

    apiClient_free(client);
    apiClient_unsetupGlobalEnv();
    return 0;
}
```

Other order functions (modify, cancel, multi-order, cancel multi-order, exit positions and GTT) take `X_Algo_Name` the same way.

## Market Protection

Market and stop-loss market orders accept an optional market price protection percentage (`-1` lets the exchange decide, up to `25`). It is the last argument of `place_order_v3_request_create`, `modify_order_request_create` and `multi_order_request_create`, and of `gtt_rule_create`:

```c
double market_protection = -1;  // pass &market_protection instead of NULL
```

## Documentation for Feeder Functions

Connecting to the WebSocket for market and portfolio updates is streamlined through two streamers in `upstox_client/feeder/` (CMake target `upstox_feeder`, which needs protobuf-c and a WebSocket-capable libcurl):

1. **Market data streamer V3** (`market_data_streamer_v3.h`): Offers real-time market updates, providing a seamless way to receive instantaneous information on various market instruments.
2. **Portfolio data streamer** (`portfolio_data_streamer.h`): Delivers updates related to the user's orders, positions, holdings and GTT orders.

Both authorize with the access token of the `apiClient_t` you pass in, run the connection on a background thread and reconnect automatically after an abnormal close. Reconnects call the authorize endpoint from that thread on the same client, so make REST calls through a separate `apiClient_t` while a streamer is running. A sandbox client cannot stream.

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>
#include "upstox_client/upstox.h"
#include "upstox_client/feeder/market_data_streamer_v3.h"

static volatile sig_atomic_t stop = 0;

static void on_signal(int sig) {
    (void)sig;
    stop = 1;
}

static void on_message(const upstox_feed_response_t *feed, void *user_data) {
    (void)user_data;
    for (size_t i = 0; i < feed->n_feeds; i++) {
        printf("update for %s\n", feed->feeds[i]->key);
    }
}

int main(void) {
    apiClient_setupGlobalEnv();
    apiClient_t *client = upstox_client_create("{your_access_token}");

    const char *keys[] = {"NSE_INDEX|Nifty 50", "NSE_INDEX|Nifty Bank"};
    market_data_streamer_v3_t *streamer = market_data_streamer_v3_create(client, keys, 2, UPSTOX_MODE_FULL);
    market_data_streamer_v3_set_callbacks(streamer, NULL, on_message);
    if (market_data_streamer_v3_connect(streamer) == 0) {
        signal(SIGINT, on_signal);
        while (!stop) {
            sleep(1);
        }
    }

    market_data_streamer_v3_free(streamer);
    apiClient_free(client);
    apiClient_unsetupGlobalEnv();
    return 0;
}
```

Modes are `UPSTOX_MODE_LTPC`, `UPSTOX_MODE_FULL`, `UPSTOX_MODE_OPTION_GREEKS` and `UPSTOX_MODE_FULL_D30`. After connecting, `market_data_streamer_v3_subscribe`, `_unsubscribe` and `_change_mode` change the subscription, and `_clear_subscriptions` forgets the tracked keys so a reconnect does not resubscribe them; `_auto_reconnect(streamer, enable, interval_seconds, retry_count)` tunes reconnection (default: on, 1 s, 5 tries). Lifecycle callbacks (`on_open`, `on_close`, `on_error`, `on_reconnecting`, `on_auto_reconnect_stopped`) are set through an `upstox_streamer_callbacks_t` and run on the streamer's thread.

`portfolio_data_streamer_create(client, order, position, holding, gtt)` takes a 0/1 flag per update type and delivers each update as raw JSON text.

See [examples/websocket/](examples/websocket/) for every function and callback, and runnable programs.

## Testing

Unit tests need no network:

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH=$(brew --prefix curl)
cmake --build build
ctest --test-dir build --output-on-failure
```

The live sanity programs port the Python SDK's `sanity.py` and `sandbox_sanity.py`. Put your tokens in [`test/sdk_tests/data_token.h`](test/sdk_tests/data_token.h) (`DATA_TOKEN_ACCESS_TOKEN`, `DATA_TOKEN_SANDBOX_ACCESS_TOKEN`), or set `UPSTOX_ACCESS_TOKEN` / `UPSTOX_SANDBOX_ACCESS_TOKEN`, which take precedence. Never commit a filled-in `data_token.h`.

```sh
./build/sanity           # live API
./build/sandbox_sanity   # sandbox
```

> **Warning:** `./build/sanity` calls the real API with your account: it places and cancels real orders, exits positions, converts a position, changes the static IP and kill switch, and logs out at the end. See [test/sdk_tests/README.md](test/sdk_tests/README.md) before running it.

## Development

The REST client — `upstox_client/api/`, `upstox_client/models/`, `upstox_client/include/`, `upstox_client/src/`, `upstox_client/external/`, `CMakeLists.txt` and `docs/` — is generated from the Upstox OpenAPI spec (copy in `api/openapi.json`) with OpenAPI Generator 7.23.0 (`-g c`). Do not edit it by hand; it is regenerated by the SDK sync process, which prepares the spec, runs the generator and re-applies the Upstox hooks in `apiClient.c` (access token, HFT and sandbox routing, SDK headers, error body).

Hand-written code lives in `upstox_client/upstox.{h,c}`, `upstox_client/upstox_test.c`, `upstox_client/feeder/`, `PostTarget.cmake`, `examples/` and `test/`.

To regenerate the market data protobuf-c types:

```sh
cd upstox_client/feeder/marketdatav3
protoc --c_out=. MarketDataFeedV3.proto
```
